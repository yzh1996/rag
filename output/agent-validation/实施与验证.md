# 统一 Agent 改造与验证

日期：2026-10-21。采用用户确认的方案 2。

## 已实现

- 默认 `AGENT_ENABLED=true`，问答直接进入同一个模型/工具循环，不进行互斥业务分类。
- 常识问题直接回答；按需发现数据、知识和计算能力，再获取完整工具与字段说明。
- 模型提出工具名称和参数；程序检查可用能力、权限、字段、只读 SQL、实际数据库结构和执行上限。
- 查询仍使用本机 MySQL 中按字典生成的模拟数据。支持已确认字段的原始、加工和汇总表，默认优先原始表。
- 计算引用实际结果的行列；店铺、直播场次、时间等已确认信息也必须引用查询依据，不能凭空填写。
- 目标、事实引用、业务依据和待补充事项保存在问答记录的 `query_details.task_state` 中。
- 恢复时检查用户权限配置、字典版本和依据有效期；内部知识重新检查当前权限与发布版本。
- 系统会话表增加可空的 `latest_interaction_id`，与问答同时保存，避免 MySQL 秒级时间导致恢复错轮次。重启后端时自动补充，业务表无需改变。
- 页面显示实际执行步骤、结果摘要、耗时、失败位置和查询依据；失败或待澄清时不生成空指标报告。
- 普通和流式接口共用上述流程；Agent 通过流式接口发送执行进度，完成查询和必要审核后发送正文。
- 达到调用或轮次预算时保留收尾机会，只依据已完成查询返回明确标记的部分结果；超时及连续失败明确提示。
- `AGENT_ENABLED=false` 可以显式回退原有流程。未增加店铺复盘的固定查询流程。

主要实现：`core/conversation_agent.py`、`core/agent_tools.py`、`core/rag_chain.py`、`frontend/agent_report.py`。
README、项目主要流程解析及示例环境配置已更新。评测配置纳入 Agent 设置和实现版本，旧发布评测需重新执行。

## 当前模型与本机 MySQL 实测

通过 `smoke.py` 直接执行 Agent，两轮均完成。此验证只读业务数据，未将测试对话写入当前问答库；API、保存和重启恢复由隔离集成测试验证。

1. 第一轮：“帮我复盘清研美妆旗舰店最新一场直播，看看整体卖得怎么样。”耗时 225.66 秒，执行 13 次工具调用。模型自主获取工具及字段说明，查询店铺与直播指标，计算比较结果，保存已确认对象与场次。
2. 第二轮：“那和上一场比呢？”耗时 255.09 秒，执行 8 次工具调用。恢复同一组场次和有效业务依据，调用计算工具完成对比，没有重新查询或更换最新场次。

已核对的模拟数据：

| 项目 | 本场 | 上一场 |
| --- | --- | --- |
| 店铺 ID | 101 | 101 |
| 直播 ID | 1000891 | 1000890 |
| 开播时间 | 2026-10-20 19:00 | 2026-10-20 10:00 |
| 销售额（元） | 7,929 | 15,663 |
| 售出件数 | 71 | 127 |

销售额变化为 -49.377514%，件数变化为 -44.094488%。第二轮复用了首轮已经查询的两场数据，因此不需要再访问数据库。

完整原始结果与执行记录见同目录 `live-results.json`。原始模型文本未经人工修改，不能将流程跑通等同于所有分析结论均已验证。

## 限制与已有问题

- 实测当前模型每轮约 4 分钟；默认处理预算调整为 600 秒，查询与轮次上限仍保留。预算不是所有客户端阻塞行为的绝对时限。
- 第二轮原始模型回答出现“主要问题在流量转化”等过度推断。金额、件数和场次已验证，但数据不包含购买转化率及因果归因，不能据此确认原因。现有 `QUALITY_GUARD_ENABLED` 可执行独立依据审核；模型建议仍需核实。
- 本地业务库是 default 租户共享模拟数据，未建设部门行级授权。其他租户不能通过 Agent 访问该库，知识权限继续沿用现有机制。
- 同会话并发控制目前在单个进程内；多进程部署需要共享并发控制。
- 旧主播分析测试 `test_agent_resolves_account_parallel_queries_retrieves_knowledge_and_summarizes` 预期 SQLite 的 `A001`，实际选择当前 MySQL 的 `1001`。该测试的业务数据源隔离不完整，未改动旧业务实现。
- 旧文档上传测试 `test_semantic_ingestion_supplies_embedding_model` 的替身函数参数与现有加载器不一致，属无关旧失败，未修复。
- 当前 `.env` 已存在第 21–23 行格式警告，未改动用户配置。

## 使用

重启后端和前端，后端启动时补充系统会话字段。无需重新造数，也无需删除现有数据。

```powershell
.\.venv\Scripts\python.exe run_api.py
.\.venv\Scripts\python.exe run_frontend.py
```

两条命令分别在两个终端运行。在同一个新会话中依次输入上述两轮问题，可展开“执行过程与数据依据”查看模型实际调用了什么。简单问题可以直接输入“GMV 是什么意思？”。
